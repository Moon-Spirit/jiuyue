# 文件存储使用本地磁盘 + Storage trait 抽象

Status: accepted

附件（图片、文件、视频）存放在**服务器本地磁盘**，通过 Rust 侧的 `Storage` trait 抽象访问，预留 S3/OSS 等对象存储的迁移路径。不引入 MinIO 等自托管对象存储。

## Considered Options

- **MinIO（自托管 S3 兼容存储）** — 被否决：常驻内存约 200–500 MB。该服务器仅 2 GB，PostgreSQL、Redis、应用、coturn、反代已在预算边缘（宿主机需预留约 768 MB），再叠加 MinIO 会直接挤压数据库内存并引入 OOM 风险。
- **直接写死本地路径**（不抽象）— 被否决：迁移到对象存储时改动会渗透进所有业务代码。

## Consequences

- 上传/下载鉴权需要自行实现（签名 URL 或后端代理），无法依赖对象存储的 presigned URL 机制。
- 路径必须分片（避免单目录堆积海量文件），且文件与数据库记录的一致性需要显式处理（先落盘再写库、失败回滚）。
- **备份必须覆盖文件目录**，而不只是数据库导出——这是一条容易遗漏的运维要求。
- 未来迁移对象存储时，只需实现一个新的 `Storage` 实现并做一次数据搬运，业务代码不变。
