# E2EE 采用双模式：云端会话 + 秘密聊天

Status: accepted

产品需要端到端加密，同时需要服务端消息搜索、多设备漫游与内容审核（公网产品的合规基础）。这三者与"全量 E2EE"在数学上互斥。因此采用 Telegram 式双模式：默认所有会话是 **Cloud Conversation**（服务端加密存储，搜索/多设备/审核全功能可用），另提供 **Secret Chat**（真 E2EE，单设备、不漫游、不可搜索、不参与审核）。

## Considered Options

- **全量 E2EE（Signal 模型）** — 所有消息一律端到端加密。被否决：它同时摧毁三个已确认的功能。
  - 服务端搜索退化为本地搜索（换设备后历史不可搜）；
  - 敏感词审核失效，而管理后台的合规处置正建立在此之上；
  - 多设备同步需要设备间密钥搬运与安全码验证，Signal 为此投入多年，成本量级不可接受。
- **不做 E2EE** — 仅服务端加密（TLS + 落库加密）。被否决：端到端加密是已确认需求。

## Consequences

- 秘密聊天不参与内容审核，其滥用只能靠举报后双方各自提供证据。这是产品定位上的**自觉取舍**，不是遗漏。
- Secret Chat 是单设备会话，与 Olm 的 device-scoped session 语义天然吻合；代价是用户必须理解"这台设备上的记录不会漫游"。
- 两套会话类型在 UI、数据模型、协议上都要有明确分支，且分支必须贯穿到管理后台（审核只覆盖 Cloud Conversation）。
