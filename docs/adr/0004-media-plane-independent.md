# 媒体平面独立部署（信令在主应用，媒体在独立模块）

Status: accepted

音视频的**信令**复用主应用的 WebSocket 连接与鉴权（1:1 通话的自建信令），但**媒体服务**作为独立可迁移模块部署：1:1 走 P2P WebRTC + coturn，群组走 LiveKit SFU。媒体服务与主应用的唯一耦合面是 REST + 回调，主应用不触碰任何媒体端口。

## 依据

- 现有服务器为 2 vCPU / 2 GB / 100 Mbps。LiveKit 官方生产建议 10 Gbps 网络，该机器比建议值低两个数量级。
- 实测数据：2 vCPU 约支撑 10–25 路并发双向视频；且 **100 Mbps 带宽先于 CPU 打满**（单路 720p 双向约 3–5 Mbps 经中继吞吐）。
- LiveKit 的**单个房间必须完整落在单个节点上**，无法把参会者分散到多台机器——因此房间规模上限由单机容量决定。
- coturn 在 Docker 中**必须使用 host 网络**（端口段 49152–65535 无法逐端口发布），并显式配置 `external-ip`，否则中继候选会返回私网地址导致连接失败。

## Consequences

- 群组通话首发按"小房间（≤4 人）可用"交付；容量增长时把媒体模块迁到独立机器，主应用代码不变。
- 1:1 通话**不经过 SFU**，因此不消耗群组通话容量，这是刻意的分流设计。
- 必须实现 coturn 的 **REST 临时凭证**（`use-auth-secret` + HMAC），静态用户名密码会在数小时内被爬取盗用。
- LiveKit 自带内嵌 TURN，可用它替代群组通话场景下的 coturn；1:1 仍使用独立 coturn。
